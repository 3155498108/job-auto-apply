# 第二次触达（未读会话补发）· 实测手册

> 适用场景：已经投过简历，但对方**还没读**；过了一两天，想再推一次。
> 硬约束：**线上已读的一律不再发**（对方看过了，再发就是打扰）。
>
> 本手册里的每条都是实测踩出来的，不是推演。

---

## 一、「已读」到底怎么判定（最容易搞错的地方）

会话列表里的 `[送达]` 标记**不能**用来判断对方是否已读。

| 你看到的 | 真实含义 |
|---|---|
| `某某HR [送达] [图片]` | 你的消息发出去了，**对方还没看** → 可补发 |
| `某某HR [已读] 好的，简历发我` | 对方看了并且回了 → **不许再发** |
| `某某HR [送达] 你好，我看了你的简历` | 带 `[送达]` 但后面跟着**对方的文字** → 对方已经回过话，**你的消息必然已被读** → 不许再发 |

所以判定必须**进到会话内部**看三件事：

1. `anyRead`：会话里**任意一条**我方消息的状态是不是 `已读`
   - ⚠️ **只看最后一条我方消息的状态是不够的**（2026-10-23 实测踩过）
   - 对方回话后我方又回了一句时，最后一条是「送达」，但更早的消息早已「已读」
   - 用户口径「线上已读的不再新投」→ 任意一条已读就跳过
2. `others`：对方有没有说过话
   - ⚠️ **不能只看「最后一条是不是我发的」**（同上，踩过）
   - 对方回过之后我又回了（哪怕只是回一句「好的」），`lastIsMe` 仍是 true
   - 对方只要回过一句，我的消息就必然已被读 → 跳过
3. 会话预览文本里有没有 `[已读]`

### 两个漏判案例（2026-10-23 真实发生）

| 会话 | 实际状态 | 为什么漏判 | 后果 |
|---|---|---|---|
| 示例企业65 | HR 说「您的经历与岗位要求匹配度不高」→ 我回「好的」 | 最后一条是我的「好的」（送达），更早的已读 | 补发已发出，随后被平台撤回 |
| 示例互动H | HR 问「有 vue 项目经验吗」→ 我回「那可能确实不太行」 | 同上 | 补发已发出，HR 可见 |
| 示例平台I | HR 问「我想要一份您的附件简历，您是否同意」→ 我回岗位详情 | 同上 | 补发已发出，HR 可见 |

**修法**：闸门从「最后一条状态」改成「**任意一条**我方消息已读」+
「**对方说过任何一句话**」两条并用。`wb_resend.py` 已按此修好。

## 二、会话列表是虚拟滚动（只拿到前 40 条就等于没扫）

- 滚动容器是 **`.user-list-content`**，不是 `.friend-list`
- 直接设 `scrollTop` **不会**触发懒加载，必须手动派发事件：

```js
var el = document.querySelector('.user-list-content');
el.scrollTop = el.scrollTop + Math.round(el.clientHeight * 0.9);
el.dispatchEvent(new Event('scroll', {bubbles: true}));   // ← 少了这行，白滚
```

- 滚到底时 `scrollHeight` 会从 7842 涨到 15642（内容是懒加载进来的）
- 判「到底了」要比较连续几次的 `scrollHeight + scrollTop`，不是固定次数

## 三、定位会话：不要用公司名，用「会话头」

同一个公司可能有多个 HR、多个岗位的会话（示例大厂J ×3、示例企业07 ×2、示例企业20 ×2）。

**会话头** = 会话预览里去掉时间前缀和状态标记之后的那段，形如：

```
昨天补先生示例大厂Jgolang开发工程师 [送达] [图片]
      └──────────── 会话头 ────────────┘
```

用会话头做 key，同公司多会话不会撞车。时间前缀要一起剥掉：

```js
s = s.replace(/^(今天|昨天|前天|\d{1,2}月\d{1,2}日|\d{1,2}:\d{2})\s*/, '');
```

## 四、三个会让你「以为点了其实没点」的坑

### 坑 1：查询和点击必须放在同一次 evaluate 里

虚拟列表在两次 HTTP 调用之间会重渲染 DOM，先查到的节点到你点的时候已经是**失效节点**，
`click()` 静默失败。必须：

```js
// 同一个 evaluate 里：找 → 点
var e = ...; e.scrollIntoView({block:'center'}); e.click();
```

### 坑 2：点开后选中态是异步的，别用固定 sleep

BOSS 是异步拉会话内容。点完立刻读 `.friend-content.selected` 读到的是**上一个**会话，
或者干脆读不到。要**轮询等待**：

```python
while time.time() - t0 < 15:
    d = read_sel_state()      # {sel, box, lis}
    if header_of(d['sel']) == target and d['lis'] > 0:
        break
    time.sleep(0.7)
```

### 坑 3：`evaluate` 返回 JS 对象时，Python 端会读到空值

`wb.py` 的 `evaluate()` 返回 `data.value` 字符串。如果 JS 直接 `return {a:1}`，
拿到的不是 JSON，`json.loads` 直接抛异常 → 后面所有字段都读成 `''` / `0`，
看起来像「全都不匹配」，其实是解析失败。

**必须 `return JSON.stringify({...})`**。

> 症状对照表：所有会话都报「会话头不符，实际=[]」，但 `pos` / `myN` 全是空
> → 十有八九是这里。

## 五、发消息会让会话置顶

发出去之后，这条会话跑到列表最顶，其他会话整体下移一格。

- 目标按列表顺序（新的在前）从小到大处理，滚动指针**只往下走**，不用每条都回顶
- 实测：按顺序处理时，下一个目标通常就在当前窗口里，不用额外滚

## 六、第二次触达的话术怎么写

**不要重发原文**。结构四段，总长 105–155 字：

1. 开场：换一个角度（不是「我是谁」，而是「怕您没看到关键信息」）
2. **一条**最硬的证据 —— 按首次投递话术的**段落标签**映射，只挑一条
3. 一句到岗承诺（可实习 / 数月以上）
4. 一句低门槛收尾（「回一句也行，我不纠缠」）

红线：

- **不带简历图**（第一次已经带过，再带就是刷屏）
- 证据只能取首次话术里**已经出现过**的原子，**不新增任何技术或数字**
- 档案单独存 `重发AI-*` 目录，**不要覆盖**首次话术目录（覆盖后无法区分「发的是哪版」）
- 开场句 / 结尾句要有多个变体轮换，否则 70 条发出去像群发

## 七、风控

- 发送间隔 **≥6 秒**
- 每 15 条歇 25 秒
- 全程带**登录态守卫**：URL 命中 `/web/user` / `login` / `passport` 立刻停
- 断点续跑：结果文件里 `status == sent` 的不再重发（脚本自带）
